# Gal4Mac 产品需求文档（PRD）

> 版本：0.1（基于截至 2026-09-26 的项目对话与仓库现状整理）  
> 状态：工作稿  
> 产品：Gal4Mac，面向 macOS 的 Galgame 游戏库与 Windows 游戏启动器

## 1. 文档依据与边界

本稿综合了项目内可访问的近期 Codex 项目对话、当前仓库源码及 README、MVP 报告、架构文档和故障复盘。对话主要涉及：从 CLI 发展为图形启动器、Mythic/Steam 风格与液态玻璃 UI、左侧导航折叠、导入归档和分卷压缩包识别、ATRi 导入问题、游戏目录快捷操作、Steam 元数据与云存档、统计看板、自定义显示名称，以及 Unity/Siglus 启动和字体、音频故障处理。

文档以仓库当前实现为事实基线；对话中提出但尚未在当前源码确认的能力不会表述为已交付。项目中存在未提交的代码和资源改动，PRD 编写期间未修改或清理这些内容。

## 2. 产品概述

Gal4Mac 帮助 macOS 用户整理并运行自己合法持有的 Windows Galgame。产品把游戏导入、引擎识别、Wine/GPTK 环境配置、启动、元数据展示和存档操作收敛到一个原生 macOS 应用中，减少用户直接管理 Wine prefix、启动参数和文件路径的负担。

### 产品愿景

成为 Apple Silicon Mac 上实用、易理解、适配中日文 Galgame 的桌面游戏库与启动器；兼容性以逐款游戏验证为准，不承诺所有 Windows 游戏均可运行。

### 目标平台

- macOS 14 或更高版本；优先支持 Apple Silicon，Intel 的支持范围需单独验证。
- Swift / SwiftUI 原生应用；运行时采用 Mythic Engine（Wine/GPTK 组件）。
- 游戏文件由用户提供。应用不分发游戏本体或未经授权的 Windows DLL。

## 3. 用户与核心场景

### 目标用户

- 在 Mac 上运行已购买或合法拥有的 Windows Galgame 的玩家。
- 拥有多款游戏，希望集中整理、搜索、查看封面和启动的玩家。
- 需要处理中文/日文显示、不同引擎设置及本地/Steam 云存档的进阶用户。

### 核心场景

1. 用户从本地文件夹或压缩包导入游戏，确认游戏目录、引擎及显示名称后加入游戏库。
2. 用户在游戏库搜索/筛选游戏，查看详情并启动；启动器应用对应的 Wine 配置和引擎优化。
3. 用户管理游戏文件夹和存档，备份/恢复存档，或从 Steam 官方页面下载云端文件后导入。
4. 用户查看游戏时间、引擎分布等统计，并在出现问题时获得清晰错误信息和排查线索。

## 4. 产品目标与衡量方式

### 目标

- 让首次导入到首次启动的关键路径清楚且可恢复。
- 让用户不必手工编辑 shell 脚本即可完成常见游戏配置和启动。
- 保护本地游戏和存档：导入、覆盖、移动等操作有明确目标与备份策略。
- 准确呈现兼容性状态，区分已验证游戏、自动识别结果和未验证引擎。

### 建议指标（待项目确认目标值）

- 导入成功率、导入中断后可恢复率。
- 已验证游戏首次启动成功率及启动失败可诊断率。
- 从打开应用到启动已导入游戏的操作步数/耗时。
- 存档导入成功率、覆盖前备份成功率。
- 崩溃率、启动器错误率、用户主动反馈的兼容性问题数。

当前仓库没有遥测或数据分析方案；默认以本地日志、兼容性矩阵和自愿反馈评估，不假定采集用户数据。

## 5. 功能需求

优先级：P0 = 核心可用所需；P1 = 近期重要体验；P2 = 后续增强。状态：已实现、部分实现、待验证、规划中。

### 5.1 游戏库与导航（P0）

- 展示已导入游戏，支持从侧栏进入游戏库、搜索游戏名称/引擎。
- 提供游戏详情，显示封面/元数据、引擎、运行时间等可用信息和操作入口。
- 支持紧凑/展开侧栏；折叠时仍显示可辨认的导航图标与可访问标签。
- 空库时说明如何添加游戏并提供导入入口。
- 近期对话期望界面更接近 Mythic 的桌面游戏库体验，并讨论了液态玻璃视觉风格；视觉实现仍需以实际窗口尺寸检查可读性、层级和布局稳定性。

状态：游戏库、导航、搜索、游戏卡片及详情已在 SwiftUI 源码中；近期 UI 重构处于未提交状态。

### 5.2 导入与管理游戏（P0）

- 支持选择本地游戏目录导入，并允许用户确认/修正识别结果。
- 支持导入时设置自定义显示名称；该名称用于库内一致展示，内部启动路径仍绑定实际目录/程序信息。
- 支持添加一个或多个游戏库目录，并扫描其中的游戏。
- 提供打开游戏目录的快捷操作。
- 支持常见归档格式的解压导入；对分卷归档识别完整分卷组，缺卷时指出缺失部分，不将不完整归档当作可安装游戏。
- 对解压、复制失败保留源文件，说明失败原因，避免产生半完成且不可识别的游戏条目。
- 对同一游戏重复导入时给出可理解的处理方式，避免静默重复或覆盖。

状态：目录导入、库管理、归档提取和近期分卷/ATRi 导入修复已进入实现；需进一步确认当前包格式覆盖、失败提示和分卷完整性验收。自定义显示名在近期项目对话中已实现于隔离工作树并提交，但该改动不一定已合入本工作目录；本稿将其作为已提出且实现待整合/核验的需求。

### 5.3 引擎识别与启动（P0）

- 自动检测可识别的 Windows 可执行程序和游戏引擎；无法判断时允许用户选择或指定启动程序/引擎。
- 启动前为每个游戏使用独立 Wine prefix，套用引擎对应配置，并避免一个游戏的配置污染其他游戏。
- 对已验证游戏提供一键启动；启动中、运行中、退出和失败状态应可识别。
- 记录必要的本地诊断日志；失败提示包含下一步建议，区分已知不兼容、缺少文件、prefix 配置和运行时错误。
- 引擎覆盖不以枚举或识别代码等同于已兼容，必须维护逐游戏验证矩阵。

状态：Unity 32 位和 SiglusEngine 32 位有项目报告的成功验证；README 记录 Aokana 与 CLANNAD。KiriKiri/KAG、TyranoScript、Ren'Py、RealLive、NScripter 等为候选/待验证。故障复盘记录了 Aokana 的 DXVK 启用修复，以及 CLANNAD 弹窗字体映射已写入但视觉结果仍待确认。

### 5.4 中日文显示、音频与运行时设置（P1）

- 为常见 CJK 游戏提供合理的 Wine locale 与系统字体映射，保留单游戏显式设置覆盖默认值的能力。
- 为每游戏应用音频默认配置，并在音频异常时展示排查建议；避免把只对特定 Wine 驱动有效的参数表述成通用修复。
- 32 位/64 位组件按目标程序架构选择；引擎资源缺失时明确说明回退行为。
- 任何 DLL 替换限定在单游戏 prefix，替换前备份并提供恢复方式。

状态：启动流程包含音频默认配置和部分 CJK 字体处理；原生 DirectSound DLL 依赖用户自行提供。音频故障复盘要求验证实际驱动效果。

### 5.5 Steam 元数据与封面（P1）

- 尝试按游戏名/AppID 获取 Steam 元数据、简介和封面；展示来源和加载状态。
- 网络失败、找不到匹配项或多语言名称不匹配时，游戏库核心操作仍可用；允许用户使用本地名称/封面。
- 缓存已获取的封面，减少重复请求并支持离线查看。
- 自动匹配结果不能覆盖用户设置的自定义显示名称。

状态：Steam 元数据服务、封面加载与缓存组件已在当前 UI 源码中；匹配准确率、缓存策略和离线体验仍需产品化确认。

### 5.6 存档管理与 Steam 云存档（P1）

- 用户可以查看/打开游戏的存档目录，备份或恢复本地存档。
- 支持导出/导入存档包；导入前展示文件数量、目标目录和同名覆盖列表。
- 同名文件覆盖前自动备份；失败时保留源归档和原有存档，允许重试。
- 支持在应用内打开 Steam 官方远程存储页面，由用户自行登录和下载，再由应用接收文件并导入用户选择的游戏存档目录。
- 不收集或保存 Steam 密码；明确展示 Steam 登录由官方页面处理。
- Steam 云端访问依赖 Steam 官方页面及用户授权。通用 Steam 云 API 并非启动器可直接读取任意游戏存档的接口。

状态：本地存档管理、归档预览/导入、覆盖备份和 Steam 页面集成已有实现。近期记录中 Steam 登录仍未完成，真实云端下载、导入并由游戏读取的端到端验证未完成；此功能不能标记为完整验收。

### 5.7 统计看板（P2）

- 提供本地游戏库统计，如游戏数量、累计运行时间、引擎分布、常玩游戏。
- 统计使用本地数据，不上传使用行为。
- 无数据时提供空状态；数值需解释统计口径，避免暗示精确到未采集的维度。

状态：近期对话提出专业化数据看板并增加图标；仓库有 `StatisticsView.swift`。统计口径和可用性需与当前工作树核验。

## 6. 关键用户流程

### 首次导入

打开应用 → 选择“导入游戏”或“添加游戏库” → 选择目录/归档 → 等待扫描与解压 → 确认识别的游戏目录、引擎、启动程序和显示名称 → 添加到库 → 查看详情或启动。

遇到分卷缺失、权限不足或格式不支持时，流程应停在可恢复状态并明确指出问题；不删除用户的原始归档。

### 启动游戏

从库中搜索/选择游戏 → 点击启动 → 显示准备/启动状态 → 应用该游戏运行配置并启动 → 记录本地运行时间 → 游戏退出后返回可操作状态。失败时提供日志位置和针对性提示。

### 导入 Steam 云存档

选择目标游戏的存档管理 → 打开 Steam 官方云存档页面 → 用户登录并下载文件 → 在 Gal4Mac 中选择待导入文件 → 预览文件与目标目录 → 确认导入 → 对覆盖文件备份 → 显示导入结果。

## 7. 非功能需求

- **数据安全**：默认数据保存在本机；清楚区分游戏目录、prefix、缓存和存档位置。高风险文件写入需预览并在覆盖前备份。
- **隐私**：不读取 Steam 密码，不上传游戏清单、游玩时长或存档内容；联网仅用于用户触发的元数据/封面及 Steam 页面操作（最终范围待确认）。
- **可靠性**：导入和更新操作可恢复；异常关闭不应使原始游戏或存档丢失。
- **可访问性**：主要按钮有清晰名称；侧栏紧凑模式保留无障碍标签；状态不能只依靠颜色表达。
- **可维护性**：按引擎配置启动行为，维护已验证游戏矩阵、复现步骤和故障记录。
- **分发**：应用包可内置 Mythic Engine；对外发布前需明确 Engine 许可、第三方组件、签名/公证和体积策略。

## 8. 暂不纳入当前版本

- 在线社区补丁中心、自动下载汉化/宽屏/成人内容补丁。
- 用户账户、跨设备云同步 Gal4Mac 游戏库。
- 自动下载或分发商业游戏本体、破解补丁或未经授权的 DLL。
- 对所有引擎、所有 Windows 游戏提供兼容保证。
- Mac App Store 发布承诺；发布渠道和 Engine 分发合规需单独评估。

## 10. 验收标准

1. 新用户能导入一个支持的游戏目录，复核识别信息并在库中看到游戏。
2. 用户设置的显示名称在侧栏、卡片、详情和相关存档操作中保持一致；实际路径和启动目标不受显示名改变影响。
3. 对已验证游戏，用户可从库启动并正常退出；未验证游戏明确显示识别/兼容性不确定状态。
4. 分卷不完整归档不会进入“导入成功”状态，并能指明缺失分卷且保留源文件。
5. 存档覆盖操作能预览目标和冲突文件，并在写入前保留可恢复备份。
6. Steam 云存档需以真实登录账户完成“下载—接收—导入—游戏读取”验证后才可标记完成。
7. 侧栏折叠、窄窗口和常见 macOS 窗口尺寸下，导航、游戏信息和主要操作仍可见且可用。
8. 元数据或网络不可用时，用户仍可访问本地游戏库并启动已配置游戏。

## 11. 待产品决策

- 首发最低支持的 macOS 版本、Intel 支持承诺及其测试范围。
- “下载游戏”入口的范围：目前需明确是导入用户已有文件，还是仅指合法发行平台的跳转/安装辅助。
- Steam 元数据是自动匹配还是要求用户确认；自定义名称与 Steam 名称的优先级已建议以用户名称优先。
- 游戏库、prefix、封面缓存、日志的默认存储位置及迁移/卸载策略。
- 是否接受任何匿名诊断数据；当前需求基线按不上传用户数据设计。
- 统计数据保留和运行时间计量方式。
- Engine 运行时的许可归属、下载/内置分发方式、应用更新和发布渠道。
- 液态玻璃视觉方向与 Mythic 风格参考之间，最终确定哪些界面样式和交互作为统一设计系统。
